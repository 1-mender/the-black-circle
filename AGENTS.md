# Правила разработки «Златогорья»

- Godot 4, GDScript, Windows, одиночная 2D RPG; базовая сетка 48×48.
- Перед изменениями изучать существующие файлы. Не удалять полезные ресурсы.
- Канон и границы этапа описаны в `docs/GAME_DESIGN.md`. Не добавлять новый канонический лор без согласования.
- Разделять данные (`scripts/data`), симуляцию (`scripts/simulation`) и отображение/ввод (`scripts/actors`, `scripts/world`, `scripts/ui`).
- Использовать простые модули, именованные действия Input Map и движение через физический цикл Godot.
- Поведение NPC выполняется локально. Не подключать внешние ИИ-сервисы.
- Не добавлять сложную экономику, глобальную политику, мультиплеер или полноценный ИИ вне согласованного этапа.
- Существующие ассеты хранить в `asset/`; временные элементы явно обозначать. Не скачивать зависимости без необходимости.
- Проверять изменения headless-импортом Godot и подходящими проверками из `tests/`; сообщать о непроверенном.
- Не публиковать проект, не отправлять файлы на серверы и не выполнять Git push без прямого запроса.
- Жизнь жителей обновлять фиксированными игровыми шагами вне визуальных узлов; сохранять совместимость старых слотов через явную версию/миграцию. Не назначать игровые действия на функциональные клавиши редактора (в частности F9).
- Имущество перемещать через PropertyLedger; не выдавать результат производства без материалов и времени. При изменении экономики проверять сохранность металла, денег и незавершённых заказов, включая загрузку и разные скорости времени.
- Бой обновлять фиксированными шагами от общих GameClock; угрозу проверять до ускоренных шагов. Пауза останавливает мир и бой, сохраняя отзывчивый UI. Мирные NPC не становятся боевыми целями автоматически. Надетые и использованные вещи учитывать в Ledger; быстрые слоты не содержат копий предметов. Тесты используют отдельные слоты в .godot/, никогда пользовательский savegame.json.
- Награды/контейнеры/вещи на земле хранить владельцами PropertyLedger, инициализировать конечные запасы один раз. Сохранять область снарядов и состояние противников; смена сцены не возрождает их. Практику навыков начислять только по результату содержательных действий, с защитой от повторного бесплатного опыта.
- Социальные действия проводить через SocialSimulation.execute/check_action. Разделять объективные события, наблюдения и трактовки; не давать NPC всеведение. Память и историю ограничивать, случайность сохранять и обновлять игровыми шагами. С 0.7 голод не управляет жизнью NPC. Обычный журнал показывает знания героя; полные сведения требуют явно включённого режима разработчика.
