# Проверка первого прототипа

Дата: 20 октября 2026 года. Среда: Windows, Godot 4.7.2 stable, NVIDIA GeForce RTX 3060 Laptop GPU.

Godot не найден в PATH. Для проверки использован уже имеющийся локальный архив `C:/Users/ASM/Downloads/Godot_v4.7.2-stable_win64.exe.zip`, распакованный во временную папку. Загрузок из сети не было. Для проверочного редактора включён portable-режим во временной папке.

## Результаты

- Headless-импорт и открытие редактора: код завершения 0, ошибок разбора GDScript и ресурсов нет.
- `tests/smoke_test.gd`: 25 успешных проверок, 0 сбоев, код завершения 0.
- Обычная главная сцена с `--headless --quit-after 120`: код завершения 0, ошибок исполнения сцены нет.
- Графическая загрузка сцены и окна разговора: успешна как с OpenGL Compatibility, так и с исходным D3D12 Forward+; оба процесса завершились с кодом 0.
- Снимки мира и диалога просмотрены: кириллица отображается, интерфейс помещается в окно 1152×720, диалог не перекрывает персонажей.

Проверки движения и ввода выполнены программно через действия Input Map. Физические нажатия клавиш в окне редактора, потеря фокуса и длительная игровая сессия вручную не проверялись. Назначение F5 проверено через настройку главной сцены и её отдельный запуск.

## Сообщения среды

При запуске Godot в ограниченной среде выводит `Failed to read the root certificate store`. В графическом режиме также сообщает о невозможности создать shader cache в `user://`. Это сообщения движка о доступе к системному хранилищу сертификатов и пользовательскому каталогу; сцена не использует сеть или файловые сохранения, проверки и рендер завершились успешно.

Первый импорт дополнительно сообщил о невозможности сохранить настройки редактора в AppData. Повторный импорт после включения portable-режима прошёл без этой ошибки. Параметр `--log-file` использован для записи проверочных журналов в `.godot/`.

Неисправностей игровой логики в выполненных проверках не обнаружено. Графика окружения и образы персонажей временные; территория не является канонической картой Златогорья.

## Исправление остановки после загрузки

F9 конфликтовала с Pause встроенного игрового окна Godot. Назначения заменены на K (сохранить) / L (загрузить), добавлены кнопки в HUD. F6 также освобождена, чтобы не конфликтовать с запуском текущей сцены в редакторе. Формат сохранения не менялся, пользовательский слот не перезаписывался.

Проверена загрузка существующего пользовательского слота только для чтения: в отдельном D3D12-процессе позиция восстановилась, пауза отсутствовала, движение работало. Источник конфликта подтверждён документацией: https://docs.godotengine.org/en/latest/tutorials/editor/game_embedding.html (Pause / F9).

Новая проверка `tests/load_input_test.gd`: 29 PASS, 0 сбоев в графическом запуске. События клавиатуры проходят через `Input.parse_input_event`: K записывает отдельный тестовый слот; L загружает из обычного состояния, инвентаря, диалога, торговли и шахты. После каждой загрузки проверено фактическое движение по D, открытие I и закрытие Escape. Кнопки HUD также проверены. Перестройка карты по клавише/кнопке отложена до окончания обработки события ввода. Снимок новых кнопок просмотрен.

Это проверка приложения в отдельном процессе; управление паузой самим встроенным редактором не эмулировалось. Защита от конфликта проверяется отсутствием F6/F9 в Input Map.
